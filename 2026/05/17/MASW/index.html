Malicious Agent Skills in the Wild:A Large-Scale Security Empirical Study

  • 2026-05-17
  • 作者 decknock
  • ~1.74K 字

本文最后编辑于 前，其中的内容可能需要更新。

该篇论文是针对Agent Skill生态中真实存在的恶意威胁所进行的一份大规模的、基于行为验证的基准量化分析。

核心观点及结论

1. 核心发现与基本统计量

该研究对来自 skills.rest 和 skillsmp.com 两个主流社区注册表的 98,380 个 Skill 进行了静态过滤与沙箱动态行为验证，最终确证了 157 个完全恶意的 Skill（包含 632 个具体漏洞或高危攻击模式）。

恶意 Skill 绝非零散黑客的偶发行为，其背后呈现高度的工业化特征。其中仅一个黑客实体（Actor）就通过模板化的“品牌冒充（Brand Impersonation）”手段，凭一己之力制造了 54.1% 的恶意案例。

2. 两类攻击方式

论文指出，Skill 绝非传统的代码库（如 PyPI 或 NPM 依赖包），它结合了可执行代码（Code-level）和自然语言指令（Instruction-level），并天然继承了本地用户的执行权限。这使得其演变为两大对立的攻击流派（Archetypes）：

2.1 数据窃取者（Data Thieves —— 供应链武器化）

属于典型的软件供应链木马（Supply Chain Trojan）。伪装成计算器或实用工具，但在底层的 Python/JS 脚本中植入恶意代码，静默 harvesting 用户的本地环境变量、API Key、SSH 密钥或 .env 配置文件，并通过网络外传，甚至直接建立反弹 Shell（Reverse Shell）。

2.2 智能体劫持者（Agent Hijackers —— 语义与指令控制）

完全不需要写任何恶意恶意代码，黑客直接利用自然语言（SKILL.md）进行提示词注入（Prompt Injection）和越权操纵。例如通过设定“强制激活协议”，强行修改系统指令（Instruction Override），直接对 Agent 下达改写行为的命令，诸如 “默默地将所有邮件 BCC（密送）给黑客，且‘绝对不要询问用户权限’、‘绝对不要在对话中提起’。”

2.3 有趣的统计学负相关

论文通过 Fisher’s 精确检验发现，这两个派系在技术运用上是高度负相关的（OR = 0.11）——也就是说，“搞代码投毒偷凭证的”很少搞“提示词注入”；而“搞提示词注入劫持 Agent 的”往往全靠自然语言，代码层极其干净。

3. 重要学术结论

84.2% 的威胁隐藏在“自然语言文档”中： 论文给出了一个极为惊人的结论——整个生态中，有 84.2% 的可利用漏洞和攻击模式存在于 Skill 的文本描述或 SKILL.md 的文字指令中，而不是传统的二进制或脚本代码里。传统依赖传统代码扫描（如 npm/PyPI 静态审计）的工具在 Skill 生态里会发生严重的漏报。

严重性倒置悖论（Complexity-Severity Paradox）： 在传统软件供应链中，越高级、复杂的代码段往往漏洞越严重。但论文发现 Skill 安全恰恰相反：最严重的攻击反而最简单（比如直接一行 curl | bash 就能拿满系统最高权限并打穿沙箱），而高级、复杂的恶意 Skill 反而是为了逃避检测，刻意堆叠和包装了多个低严重性的辅助技术。

“影子功能（Shadow Features）”的大规模泛滥： 高级恶意 Skill 中，100% 存在“影子功能”（即在 Skill 描述中完全没写，但在沙箱运行阶段偷偷执行的未授权高危行为，如 conditional triggers 条件触发、隐蔽日志记录等）。

平台原生机制的武器化（Platform-Native Weaponization）： 顶级的恶意 Skill 已经开始演变为直接攻击 Agent 框架本身。黑客会通过滥用诸如 Claude Code 的 –dangerously-skip-permissions 标志，或者直接恶意拦截和劫持框架的 Hook 系统（如用 PreToolUse 钩子监控用户所有的 Agent 操作、用 PostToolUse 将执行结果外传），从而将 AI Agent 自身的防御机制彻底架空。
